# 动力学补偿与控制频率离线排查

## 结论等级

**已复现一处直接危险的数值缺陷：生产代码 Kernel::Filter::FilteredResCal() 的协方差更新错误，
会从有界、连续的小输入产生数百倍放大的尖峰。该方法直接用于惯性补偿中的加速度估计。**

频率和滤波时间参数存在其他已确认不一致；其中最重要的影响是相同滤波迭代数在 300 Hz
下更早到来，以及稀疏目标被压进更短的插补时间窗。尚未完整复现真机事故的物理闭环、
异常反馈后的重新限幅和日志中的 -44114 峰值，不能把当前实验当作事故唯一根因的最终鉴定。

本轮只在此目录创建隔离实验和报告，没有修改生产控制源码、运行参数或安装产物，
没有启动 ROS 节点、CAN、EtherCAT 或发送机器人指令。

## 1. 原始 C++ 可重复复现滤波缺陷

测试直接编译当前 `ros2_ws/src/dual_arm_control_hw/src/controller/JntController.cpp`，
不是将滤波函数重写成 Python。隔离 config.h 仅声明未用到的 TEMPTIME 全局变量，
用于避免引入 ROS/硬件依赖。诊断程序只访问 Filter 内部状态并保存 CSV。

输入和参数：

```text
输入 = 0.01 * sin(2*pi*2*n/300)
Qgain = 1
Rgain = 0.01
P0 = diag(1000000, 1000000)
调用 36000 次
```

Qgain/Rgain/P0 与当前加速度滤波配置和生产类一致。

| 项目 | 原始 C++ 结果 |
|---|---:|
| 输入绝对值上界 | 0.01 |
| 输出绝对值峰值 | 8.596901 |
| 内部标量增益绝对值峰值 | 2070.815942 |
| 首次 P[0,0] 为负 | 第 14739 次调用 |
| 输出最大值所在调用 | 第 20766 次调用 |
| 同文件中旧方法对相同输入的输出峰值 | 0.012570 |

以 -O2 与生产构建所用的 -O3 -DNDEBUG 分别编译，两个完整 CSV 逐字节一致。
另由已记录增益独立重建 `y[n]=y[n-1]+K[n]*(x[n]-y[n-1])`，与 native 输出差为 0。

这里的“旧方法”是同一文件保留的 FilteredResCaloldVersion()，仅作算法对照，
**不表示 10 月 31 日的程序选择了该方法，也不表示直接切换到它已获真机验证。**

### 具体代码错误

位置：`JntController.cpp:184–206`。

1. 预测协方差实际计算 `F*P + Q`，缺少右乘 `F^T`；应为 `F*P*F^T + Q`。
2. 只计算第一个状态的标量增益 K，却把它作为第二个状态的增益使用：
   更新矩阵写成 `[[1-K,0],[-K,1]]`，不是与预测协方差一致的二维 Kalman 更新。
3. 状态更新只更新 outvar[0]，第二状态 outvar[1] 没有对应的观测更新。

第一轮协方差已明显不对称（P01-P10 约 999999.9999）；后续 P00 变为负数，
分母 `P00 + R^2` 可逼近零，造成负增益、超过 1 的增益和极大尖峰。
这不是普通的“滤波强度不合适”。

### 如何进入前馈

```text
目标速度
 -> (v_now-v_last)/temp_T
 -> acc_ftr[i].FilteredResCal()        [ArmController.cpp:1714]
 -> mass_matrix * a                   [ArmController.cpp:1736]
 -> 惯性/科氏补偿
 -> 中层输出与伺服插补
 -> joint_tor 与重力项等相加
 -> 协议打包
```

gravComp.ifUseGravComp=1 时，关节回放进入 compMod=1，激活这条完整动力学路径。
生产滤波文件与 10 月 31 日备份逐字节相同；当时补偿开关为 0，
不能据当时回放较正常推断此滤波实现安全。

## 2. 频率相关问题

### 2.1 错误滤波器更早进入危险迭代阶段

同样的第 14739 次调用，按稳定每周期调用一次换算：

| 调用频率 | 对应时间 |
|---|---:|
| 50 Hz | 294.78 秒，约 4 分 55 秒 |
| 300 Hz | 49.13 秒 |

合成输入实验的主要尖峰集中在约第 49–71 秒（300 Hz）。
这支持“节点运行一段时间后才出现、短片段通过不能覆盖”的机制；
不意味着每次都恰在同一秒发生物理甩动。
实际加速度滤波器开始更新的准确时刻、完整 300 Hz 输入及各回调调度没有被现有 20 Hz
日志完整记录，因此不能把某个迭代点直接等同于事故时刻。

### 2.2 Kalman 内部写死了 1 ms

`JntController.h:107–110` 的 F 和 Q 均按 dt=0.001 构造；
它没有接收当前中层控制周期。当前中层为 dt=1/300 秒，历史中层为 0.02 秒。

**另一个容易混淆的点已核实：** ForceComp_floatBase 的速度差分分母 temp_T
来自 TEMPTIME，当前确实是 1/300 秒，未发现这里仍按 1 ms 除的证据。
写死 1 ms 的位置在 Kalman 模型内部，不能把两处混为同一个问题。

### 2.3 一阶低通系数定义与使用相反

代码定义：`alpha=1-exp(-2*pi*fc/Fs)`，这是新输入的系数，
更新时却写成 `alpha*old + (1-alpha)*input`。

| 当前配置 | 实际旧输出权重 | 实际新输入权重 |
|---|---:|---:|
| 输入 Fs=10000、fc=20 | 0.012488 | 0.987512 |
| 输出 Fs=50、fc=20 | 0.918997 | 0.081003 |

输入滤波几乎直接通过新样本；输出滤波保留了很强的历史项。
实际调用频率变为 300 Hz 后，这些固定系数对应的真实时间响应也改变了。
这些一阶系数本身为正且和为 1，不会单独将有界输入放大到数万；
但它们改变了进入差分及错误 Kalman 滤波器的信号和相位。

### 2.4 15 Hz 数据目标被按中层一个周期处理

上层发送 `upper_monitor_time=TempTime`（当前 1/300 秒），
ctl_trans_mod=3 对应 runinMod=1。中层一次线性插补的时长因此为一个中层周期。
回放目标却是每约 66.7 ms 才更新一次。

这使内部原始速度成为 `delta_q/dt` 的脉冲：相同位置变化从 20 ms 压到 3.33 ms，
速度脉冲可增至约 6 倍，差分加速度可增至约 36 倍，再进入滤波和动力学补偿。
这说的是内部规划量，不是断言实际机械臂速度必然放大同样倍数。

## 3. 使用实际轨迹和 Pinocchio 的隔离试算

使用本次事故 CSV 中的原始 300 帧目标、当前安装 URDF、当前参数和原生 C++ 加速度滤波器，
构建无物理反馈的开环试算：理想 15 Hz 目标到达、先保持首帧 65.2 秒，再执行目标序列。
65.2 秒是用于覆盖该次运行时长附近的实验条件，不是根据完整原始调度逐周期还原的状态。

| 隔离实验 | 最大滤后加速度（14 轴） | 左 J1 惯性补偿绝对峰值 | 14 轴总前馈绝对峰值 |
|---|---:|---:|---:|
| 当前算法，300 Hz | 21641.86 | 29.3145 | 29.0721 |
| 相同算法，50 Hz | 17.23 | 0.0298 | 0.5168 |
| 300 Hz，仅用同文件旧 Kalman 方法作对照 | 46.75 | 0.2132 | 0.5292 |
| 300 Hz，仅改为正确低通系数和实际 Fs | 23934.09 | 71.1826 | 165.7270 |

加速度单位 rad/s²；前馈为模型内部力矩字段，不是实测电机输出。
所有 300 个原始目标姿态处的臂部质量矩阵均为正定，最小特征值约 3.23e-5；
纯重力项在这些姿态上有限。暂未发现通过“原始姿态处质量矩阵已非正定”解释尖峰的证据，
但模型的物理参数精度仍未经过实物标定。

**不能仅修正低通系数就上线。** 该隔离例子里，单独修正低通反而让某些轴尖峰更大。
错误 Kalman 更新必须优先解决，随后再一起设计实际周期、重采样和滤波参数。

该开环计算不含真实电机、反馈闭环、事故后反馈裁剪、伺服插补、所有中间调度抖动及现场接触，
没有精确复现日志 -44114 的后续峰值。它的作用是验证危险计算路径和不同因素的影响。

## 4. 后续修复范围

1. 先对加速度估计建立数学一致、周期明确的滤波器，验证协方差对称、半正定和长时间有界性。
2. 把逐帧目标的时间间隔与控制循环周期分开，不把稀疏目标压到一个高频周期；
   位置、速度和加速度应来自同一条有明确约束的连续轨迹。
3. 按实际调用周期统一低通和其他滤波参数，使用明确的新样本权重定义。
4. 在隔离仿真中检查补偿开关、目标更新频率、启动/暂停/重启、反馈缺失和姿态越界组合。
5. 另行处理此前已确认的前馈异常拒绝、逐电机有效反馈和故障锁存；
   修正数值算法不等于已具备故障保护。

本轮没有把任何实验替代算法写回控制程序，也没有提供恢复真机运行的参数。
