# 机械臂只读异常监测

此模块用于收集偶发掉落、失联及恢复时的线索。它只读取命令和反馈，**不会停止、失能、限速、
改变 Kp/Kd 或阻止追踪旧目标**。当前运动及自动回零行为保持原样；这不是防坠或故障恢复保护。

## 开关与使用

配置在 `ros2_ws/src/ctl_msgs_hw/config/controllerConfig.yaml` 的 `armMonitor` 中，
当前默认 `enabled: true`。缺少整个配置块时默认关闭，兼容旧配置。
修改开关或阈值后需要同步安装配置并重启 servo，不支持运行中切换。

只改配置时，在项目根目录执行：

```bash
bash scripts/build.sh --packages-select ctl_msgs_hw
```

本次源码更新需要构建 `servo_control_hw`（已在交付时构建验证）。按原有启动顺序操作。
重新链接可能清除可执行文件的 EtherCAT capabilities；正式运行前执行原有 `make build`
流程，由它通过 sudo 恢复网络权限。构建和离线验证本身不需要启动机械臂。
以下 `make servo` 命令会照常启动机械臂、执行现有初始回零；启动参数只覆盖记录开关。

```bash
make servo ARGS="--ros-args -p arm_monitor_enabled:=false"  # 本次启动关闭
make servo ARGS="--ros-args -p arm_monitor_enabled:=true"   # 本次启动开启
```

关闭时不创建记录线程或日志文件，观察钩子只检查开关。开启时启动消息会显示日志目录。
默认路径相对于启动工作目录；从项目根目录启动时为 `outputs/arm_monitor/monitor.csv`。
可以把 `log_directory` 改成有写权限的绝对路径。

```bash
python3 scripts/summarize_arm_monitor.py
python3 scripts/summarize_arm_monitor.py /absolute/path/to/log_directory
```

异常发生后及时复制整个日志目录。默认保留当前文件和 3 个历史文件，每个约 64 MiB，
合计约 256 MiB（每个文件可能超出一行及表头）。`monitor.csv` 最新，`monitor.1.csv` 次新；
每次启动或文件达到大小上限时轮转。旧记录最终会被覆盖，保留时长取决于采样周期及每行大小。
汇总中的 `marked_windows` 是包含标记的**采样窗口数**，不是独立故障次数。

## 采集范围与解释

监测主控制、启动回零和机械臂标定的 `EtherCAT_Run()` 命令交换。日志 `phase` 区分
`homing`、`running`、`calibration`。初始的直接参数查询和专用 CAN 扫描不纳入这份记录。
当前轴映射固定为 CAN0/ID1–7 → 左臂 l0–l6，CAN1/ID1–7 → 右臂 r0–r6；夹爪不参与。
如果日后改变通道或 ID 编排，需同步修改监测映射。

- 记录每次控制交换前的逻辑关节目标、速度、前馈、Kp/Kd 和控制模式。
  这些是**方向补偿及协议打包限幅之前**的值，不是驱动实际执行值；前馈也不是总输出力矩。
- 正常模式记录完整 ACK1 帧的原始解码位置、速度、电流、温度及错误位。
  使用现有协议的编码范围；编码范围不代表机械允许范围。
  WKC 不足、ID 不匹配、短帧、其他 ACK 不会刷新监测中的完整反馈。
- `decode_age_ms` 是距最近一次成功读取并解码完整 ACK1 PDO 的时间；从未解码为 -1。
  当前网关没有暴露逐电机 CAN 接收序号或硬件时间戳，**不能将此值当作真实 CAN 接收新鲜度**。
  即使 WKC 正常，也可能反复读到缓存的电机反馈。
- `unchanged_age_ms` 表示反馈载荷内容多久没有变化，辅助识别冻结；静止电机也可能长期不变，
  因此此字段不单独触发异常标记。文件头写有 `hardware_can_freshness=unknown`。
- `command_age_ms` 使用单调时钟计量上层回调的接收间隔，与 ROS 时间戳独立。
  `ros_latency_ms` 仅记录原有 ROS 时间差。接收命令不代表目标产生端仍然在线；
  中层持续重复发布旧目标时，需要结合目标/反馈及上层信息判断。

默认每 50 ms 保存一行，但每次控制交换都检查并累计窗口内峰值和标记；持续时间不足 50 ms 的
偏差、速度或丢包仍可进入 `window_flags`、峰值和累计计数。每行只有末次状态和窗口统计，
不能重建窗口内全部 1 kHz 轨迹或精确事件顺序。

`flags` 表示末次交换的标记，`window_flags` 是从上一条成功入队记录开始的标记按位或：

| 位值 | 名称 | 条件 |
|---|---|---|
| 1 | command_timeout | running 阶段，已经收到过命令，距最近命令超过 100 ms |
| 2 | bad_wkc | 当前 EtherCAT WKC 低于期望值或期望值无效 |
| 4 | decode_missing | 某轴完整 ACK1 解码间隔超过 100 ms，或启动后一直没有完整解码 |
| 8 | tracking_error | 位置类输出与未超出解码时间阈值的反馈相差超过 0.35 rad |
| 16 | fast_feedback | 反馈速度绝对值超过 2 rad/s |
| 32 | target_step | 同模式连续两次输出的关节位置变化超过 0.10 rad |
| 64 | loop_gap | 相邻受监测交换的起始时间间隔超过 5 ms |
| 128 | invalid_numeric | 观察到 NaN/Inf 等无效数字 |
| 256 | motor_error | 最近完整 ACK1 中带有电机错误位 |
| 512 | special_output | 本轮使用特殊原始队列，普通关节目标不描述该输出 |

这些是初始诊断阈值，未经真机标定。启动回零、较快任务及人工拖动可能产生预期标记，
需要按 `phase` 和现场动作解释。首次命令到来前 `command_seen=0`，不标记命令超时；
标定和回零也不依赖上层持续发送命令。电流模式不进行位置偏差/位置步长检查。

所有 `*_mask` 按位映射 14 轴（bit0=l0，bit7=r0）。`output_mask`、`decoded_mask`、
`missing_mask` 分别表示本轮普通输出、曾成功解码、当前解码缺失的轴；
`error_mask`、`speed_mask`、`step_mask`、`fault_mask` 记录窗口中触发相应条件的轴。
未曾解码的数值字段默认 0，必须结合 `decoded_mask` 阅读，不能把 0 当作有效反馈。
文件首行包含采样阈值、单调时钟原点和 Unix 时间原点，用于关联多个进程会话。

## CPU、磁盘和记录故障

控制线程只执行固定 14 轴检查、少量单调时钟读取和有界队列复制；新增观察路径不分配内存、
不等待锁、不写盘、不逐帧打印。CSV 格式化、写盘和轮转在一个后台线程中完成。
队列固定为 256 条，满时丢弃本次采样并增加 `dropped_samples`，继续累计窗口峰值，
不会为了等待记录而阻塞控制循环。队列内存大小固定。

配置异常、无法创建目录或后台写盘失败会关闭记录，并输出一次原因；不改变机械臂输出。
后台线程与控制共享 CPU 和文件缓存，因此仍有间接调度/内存带宽开销，不能保证真机零影响。
后台通常每秒 flush；正常退出会排空已入队记录。尚未到采样时刻的最后一个窗口、
强制杀进程或整机掉电前的缓存数据可能丢失；没有逐行 fsync。

## 离线验证

`tests/test_arm_monitor_cpp.py` 包含单调时钟异常注入、300 Hz 命令/1 kHz 伺服时序、短暂异常
恢复后保留峰值、反馈过期、重复载荷、短帧/错误 ID/WKC 拒收、方向/单位、日志轮转和记录失败检查。
另用 mocked SOEM 和实际打包函数逐字节比较开关前后的 MIT、位置、电流及特殊队列输出，
并比较反馈结果。测试不访问网卡或机械臂。

`tests/arm_monitor_test.cpp` 的 `--benchmark` 模式可进行 1 kHz、14 轴、20 Hz CSV 写盘的
离线开关对比；它包含后台线程 CPU 时间，实际 EtherCAT 和 ROS 负载不在此测试范围内。

2026-11-01 在当前机器进行 3000 轮/3 秒每组的离线对比：关闭时钩子平均 0.223 μs/轮，
开启时 1.783 μs/轮，平均增加约 1.56 μs。包含后台写盘的进程 CPU 占用分别约为单核心的
0.49% 和 1.60%，增加约 1.1 个百分点，未丢弃采样。开启时该次观察到的钩子最大耗时为
4.43 μs；它不是最坏耗时上界，也不能替代真机带完整 ROS/EtherCAT 负载的评估。
